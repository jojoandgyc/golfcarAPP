# App 电机配置分页

“电机”分页用于读取双路驱动器的参数，并保存经过校验的配置。左右电机属于同一从站；此页不发送目标转速、启停、抱闸、相序学习或恢复出厂指令。协议依据、地址、范围与文档歧义见 [协议审核](motor-configuration-protocol-review.md)。

## 使用方式

1. 连接开发板，先正常结束手动驾驶和自动跟随。跟随退出尚未确认时，配置保持锁定；重连后的只读占用检查确认空闲后才继续。
2. 打开“电机”，点击“读取当前配置”。切换到页面本身不会打开串口或自动读取。页面显示本次设备信息、左右电机观测和只读参数，不作为持续实时监控。
3. 修改最大输出电流、正转速度上限、反转速度上限、闭环加速度或闭环减速度。未读到当前值、读值失效或输入无效时无法保存。
4. 点击“应用已改项”，核对每项旧值、新值和单位，再点击“确认写入并保存”。只提交已改的五项白名单参数。
5. 查看每项结果。只有“回读一致”表示已经收到写入回执且读回原始字与请求相同；其他项目按各自状态处理。未全部确认时先重新读取，不直接重发。

页面上的速度限制是驱动器 RPM，不能当作车辆 km/h。电流输入精确到 0.01 A。最大输出电流还受设备能力和已读左右驻车电流限制；不能将上限降到任一侧现有驻车电流以下。电子驻车、系统模式、通讯、相序、转弯上限和堵转时间在此页只读，手动页既有的临时驻车控制不因此删除或迁移。

保存采用协议规定的 `0x10` 断电保存功能码，并逐项读回；它不等于已经验证重启后的实际保持，也不自动重启驱动器。配置草稿与控制器读值分开显示，切页不会自动保存。连接丢失、开始控制或上次写入结果未知后，必须重新读取。

## 互锁与失败处理

App 在配置读写期间阻止竞争的手动、跟随、终端和视频操作，并核对确认预览对应的当前草稿，避免重复提交。断开连接可以取消等待；已经发出的写入不能据此判断为未发生，界面会标明结果未确认。

板端桥接独立执行以下检查：

- 固定串口 `/dev/ttyS0`、115200、8N1、从站 1，不接受 App 传入任意串口、地址、波特率或寄存器地址。
- 使用现有手动／跟随锁，检查控制进程和串口占用。锁文件缺失、无法完整检查或控制忙时拒绝，检查本身不创建锁文件或终止进程。
- 串口打开后检查已有独占标记，再取得本次独占并复核除自身之外没有占用者；这些检查完成后才设置串口和发送协议数据。失败只撤销本次取得的独占标记。
- 写入前要求两次观测左右零转速、零 PWM 和通讯控制来源，并在每一项实际写入前重新观测、核对预期旧值。零速是观测，不宣称驱动已禁能。
- 每项只使用允许的 `0x10` 地址／字数，核对 CRC、回执和 `0x03` 读回。任一异常停止后续项目，不自动回滚或重新发送整个批次。

多项保存不是硬件原子事务，先成功的参数可能已经生效。结果区区分回读一致、已收回执但未确认读回、写入结果未知、处理失败和未尝试。检查失败只报告固定错误码，不把任意命令输出或凭据放入诊断日志。

## 桥接部署

App 固定调用：

```text
sudo -n /usr/bin/python3 -B /home/topeet/lianzhan/scripts/app_motor_config_bridge.py --request
```

请求为有长度限制的 stdin JSON，响应为一行 JSON，包含请求编号、协议版本、快照和逐项结果。参数不拼进 shell 命令。App 和板端必须使用匹配的 schemaVersion；返回缺字段、错编号、真实／模拟类型不匹配或成功条件不一致时，不显示保存成功。

部署文件是 `board/app_motor_config_bridge.py` 与 `board/app_control_guard.py`，后者需与桥接位于同一目录供导入。部署前确认控制空闲，备份目标旧文件并记录其哈希；安装两文件后核对目标文件哈希、所有者和权限。它们不替换现有跟随、手动、GUI 或驱动程序。实际部署版本、哈希及备份路径应填写在下方验收记录，不以源码存在作为部署完成。

部署后可先执行不打开串口的检查：

```bash
sudo -n /usr/bin/python3 -B /home/topeet/lianzhan/scripts/app_motor_config_bridge.py --check
```

只有 `ok=true`、`controlAvailable=true` 且 `serialOpened=false` 才表示这个检查通过；仍未读取控制器，也未验证实际写入。若 `sudo -n`、固定路径或锁检查失败，App 报告部署／占用错误，不尝试其他命令或降低检查要求。

## 验证与验收记录

离线 Python 测试入口：

