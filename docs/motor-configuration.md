# App 电机配置分页

新版“电机”页覆盖手册中的 **69 项配置、22 项只读信息和 8 个控制接口**，按 7 个分类查看。配置和控制均通过明确的预览、确认操作提交；进入页面、切换分类、搜索和编辑草稿都不会访问电机串口。

本次版本为 `1.8-motor-full` / versionCode 11，App 与桥接使用 `schemaVersion=2`。**本次仅开发及模拟验证，不部署开发板桥接、不安装到用户手机、不读取或修改已调好的实车参数，也不运行真实电机。** 文末保留的旧版部署记录不能作为新版已部署的证明。

完整地址、单位、范围、选项和文档歧义见 [寄存器目录](motor-register-catalog.json)；协议依据见 [协议审核](motor-configuration-protocol-review.md)。保留地址不提供读写入口。

## 页面分类

| 分类 | 内容 |
| --- | --- |
| 概览 | 设备信息、当前访问使用的串口参数、读取时间、左右电机状态、其他只读寄存器、最近配置写入和控制操作结果 |
| 电机 | 27 项：通用电流与速度限制、霍尔/传感器设置、左右极对数、相序、电子驻车电流、FOC 角度和反向设置 |
| 保护与模式 | 8 项：电压保护、系统/闭环模式、差速转弯上限、堵转时间和过流阈值 |
| 抱闸 | 4 项：左右抱闸输出类型、停车刹车设置 |
| 通信 | 11 项 RS485、CAN、TTL 配置，以及独立的“本次 RS485 连接”设置 |
| PID | 19 项速度环、D/Q 轴和驻车控制参数 |
| 操作 | 左右停止、左右目标速度、左右抱闸、恢复出厂、相序学习/取消，共 8 个逻辑接口 |

参数分类支持按名称或寄存器地址搜索，左右电机、各通讯接口和 PID 环分组展开。每项显示寄存器地址、读取值、单位、允许范围和手册备注；枚举使用带含义的选项，输入框中的值只是草稿。

概览中的状态是**上次主动读取的快照**，不持续刷新。零 RPM 或零 PWM 都不能单独证明驱动输出已禁能、车辆已停稳或机械抱闸已闭合。

## 读取与修改配置

1. 连接开发板，正常结束手动驾驶和自动跟随。控制退出未确认时保持锁定；重连后的占用检查确认空闲后才继续。
2. 打开“电机”，点击“读取当前配置”。没有有效读取值的参数不能编辑；读值失效或串口连接设置变化后，需要重新读取。
3. 选择分类和写入模式，修改需要调整的项目。每项显示读取值与待写值的差异；未改的项目不提交。
4. 点击“预览配置改动”，检查所有项目的旧值、新值、单位、寄存器及写入模式，再点击“确认临时写入”或“确认写入并保存”。
5. 点击“查看写入结果”或返回概览，逐项核对结果。出现未知或未确认结果时先重新读取，不直接重复发送。

| 写入模式 | 协议和行为 |
| --- | --- |
| 断电保存 | 使用 `0x10` 完整写入参数，并按驱动器协议保存；每项随后读回核对。不会自动重启驱动器，因此回读一致不等于已验证断电后的保持情况。 |
| 临时设置 | 50 项支持 `0x06` 临时写入，不写入断电存储。正转最大速度、反转最大速度和最小转速这 3 项 32 位参数分两帧写入，按中间值不越界的字序处理；PID 的 19 项仅支持断电保存。 |

切换写入模式、修改草稿、重新读取、连接变化、控制锁定或开始其他操作都会使旧预览失效。切页不自动保存。多项写入不是硬件原子事务：先成功的参数可能已经生效，异常后停止后续项目，不自动回滚或重发整个批次。

三项转速的双字临时写入也不是原子操作：前一帧可能已经生效。任一帧异常都会停止后续发送，按未知结果处理并要求重新读取；不把中间值或部分回执当作完整参数写入成功。

输入和编码需要注意：

- 速度使用驱动器 RPM，不是车辆 km/h；电流以 A 输入，相关字段精确到 0.01 A。
- 最大输出电流与两侧驻车电流按本次修改后的组合校验，仍受设备能力限制；板端安排写入次序，避免中间状态出现驻车电流超过最大输出电流。
- FOC 角度允许带符号小数。相序成对输入，例如 `1,2` 表示低字节相位 1、高字节相位 2，每个相位值为 0–6。
- 除目录注明直接使用原始值的霍尔驻车速度环 P 外，Q15 PID 显示值为原始值除以 32768。输入必须能精确编码，不静默舍入。
- 手册中的超出单寄存器容量的上限、模式保留值等歧义在对应项目备注中显示；按可编码范围和明确枚举校验，不推测保留值含义。

## 单次控制操作

“操作”分类与配置草稿分开。选择操作及参数，点击“预览本次操作”，核对寄存器、具体请求值、可能影响和最长执行时间，再点击“确认执行”。每次确认只对应当前这一条请求，不构成对以后操作的授权。

| 接口 | 请求值与限制 |
| --- | --- |
| 右电机停止 `0x0040` | 正常、紧急或自由停止。独立模式作用于右侧；同源和差速模式作用于两侧。 |
| 右 / 直行目标速度 `0x0041–0x0042` | 有符号 RPM，实际还受已读正反转速度上限约束；最长执行时间 100–3000 ms，到时请求停止。 |
| 右电机抱闸 `0x0043` | 按手册选断开或闭合抱闸输出，需核对接线及抱闸输出配置。 |
| 左电机停止 `0x0044` | 正常、紧急或自由停止，仅独立模式有效；同源和差速模式使用右侧停止接口。 |
| 左 / 转弯目标速度 `0x0045–0x0046` | 独立模式控制左侧，差速模式控制转弯，同源模式无效；受速度/转弯上限约束，限时 100–3000 ms 后请求停止。 |
| 左电机抱闸 `0x0047` | 按手册选打开或关闭抱闸输出；回执不证明机械抱闸已完成动作。 |
| 恢复出厂参数 `0x0048` | 单独预览并确认；会覆盖已调好的参数，也可能改变通讯设置。执行后重新核对连接参数并读取。 |
| 相序学习 / 取消 `0x0049` | 选择左侧学习、右侧学习或取消测试。学习限时 100–60000 ms 后发送取消；取消请求不带持续时间。 |

限时速度/学习由板端管理收尾。在执行结束、异常或检测到请求所属进程失效时，板端尝试停止/取消；原操作不自动重试。离开电机分页、App 进入后台或窗口失焦时，App 会取消在途限时动作的 SSH 等待，板端按所属进程退出规则尝试收尾；页内也可点击“取消操作并核对状态”。普通配置写入不会因这些可见性事件被中途取消。连接中断时 App 不能据“等待已取消”宣称动作没发生或已经停止，仍需核对板端与实车状态。

停止与取消使用独立的允许条件：在板端已确认控制占用允许时，不因普通参数写入所需的零速/PWM 或通讯控制来源条件而一并禁用；它们仍不能绕过 App 控制互锁、串口独占和当前快照检查。其他动作需要板端允许普通写入，并检查当前系统模式及参数限制。

收到操作回执只表示对应协议指令得到响应，**不证明车轮停稳、机械抱闸完成或相序学习成功**。界面分别显示指令结果和停止收尾是否确认。每次操作完成后需要重新读取，旧快照不会直接用于下一次执行。

## 通信参数与重新连接

通信页中的两类设置含义不同：

- **本次 RS485 连接**：设置 App 下一次访问控制器采用的从站地址、波特率和校验格式，点击“使用此连接参数”只保存 App 设置并使旧快照失效，不写控制器，也不自动读取。固定串口为 `/dev/ttyS0`；支持从站 1–254、9600/19200/38400/57600/115200 bps、8N1/8E1/8O1/8N2，默认从站 1、115200、8N1。
- **驱动器通信寄存器**：属于真正的配置写入。改变 RS485 地址、波特率或校验方式可能立即断开当前链路，因此这三项要求单项提交。收到回执也标为需要重新连接，不在旧参数下冒充回读成功、不自动扫描或重复写入；根据确认的目标参数设置“本次 RS485 连接”后重新读取。

CAN 与 TTL 配置也可查看及修改，但本页实际访问通道仍为固定 RS485 串口，不会自动切换到 CAN 或 TTL。手册配置地址范围包含 0/255，App 的访问参数只允许可确认单播的 1–254；有关边界含义见各字段备注。

## 互锁与未知结果

App 在配置读取、写入和单次操作期间阻止竞争的手动、跟随、终端及视频操作。预览确认时再次核对当前快照、草稿、连接参数和忙碌状态，旧确认不直接复用。SSH 断开后更新连接状态，已发出的操作结果保持“未知”，不会自动重启或重发控制。

电机控制指令发送前先持久化独立的恢复锁，保存失败时不发送指令。任何失败、取消、未知结果或停止收尾未确认都会保留锁，重连及 App 重启不能清除；驾驶、跟随、终端、视频、配置写入和新的电机动作保持禁用。明确成功且无重连要求的动作回执可解除该锁；限时动作还必须确认停止收尾，任何 `cleanupConfirmed=false` 都不能解锁。恢复锁排除系统备份。

锁定后仍允许恢复蓝牙配网/Wi-Fi Direct、重新连接 SSH，以及在通信分类修正 App 使用的串口参数。恢复网络本身不解除锁。用户主动点击“读取当前配置”，并由板端确认控制空闲、两次零速/零 PWM 观测及通讯控制来源后，才可持久化清除恢复锁；读取失败或清锁保存失败继续锁定。这些读取条件是访问恢复依据，不等同于对车辆物理停稳的保证。跟随占用检查、普通重连及其他后台查询不能代替这次主动核对。

板端独立执行以下检查：

- 使用固定串口与允许的连接设置、寄存器、字数及功能码白名单，不接受任意串口路径、任意地址或任意原始帧。
- 通过现有手动/跟随锁、进程检查和串口独占确认访问条件；无法完整确认时拒绝，不终止现有控制程序。
- 普通配置写入要求两次读取的左右零速、零 PWM 及通讯控制来源；每项写入前重新核对状态和预期旧值。停止/取消按上文独立条件处理。
- 校验长度、CRC、异常功能码、写入回执和配置读回；协议异常后停止该会话的后续普通事务。
- 限时动作记录并尝试停止/取消收尾；是否确认单独返回，不将收尾异常改写成动作从未执行。

| 界面结果 | 含义与下一步 |
| --- | --- |
| 回读一致 | 该配置已收到写入回执，且读回原始字与请求一致。 |
| 已收写入回执，回读未确认 | 写入可能已生效；通信链路参数修改也会出现此状态。先检查连接参数并重新读取。 |
| 写入结果未知 / 指令结果未知 | 请求可能已到达设备；先核对状态，不直接重试。取消等待、超时或断连都不能证明没有写入。 |
| 处理失败 | 按具体错误和逐项结果处理，其他已成功项目不自动回滚。 |
| 尚未尝试 / 未发送 | 该项尚未发送，不等于同一批此前项目都未执行。 |
| 停止收尾未确认 | 无法确认停止/取消指令回执；不能据此显示实车已停止。 |

诊断日志记录操作类型、字段标识、结果和固定错误码，不把凭据、任意命令正文或输出写入日志。

## 桥接版本与部署边界

App 固定调用以下入口，请求参数通过有长度限制的 stdin JSON 传递，不拼进 shell：

```text
sudo -n /usr/bin/python3 -B /home/topeet/lianzhan/scripts/app_motor_config_bridge.py --request
```

新版响应是一行 `schemaVersion=2` JSON，带请求编号、真实/模拟标记、快照、配置逐项结果或动作结果。App 拒绝不匹配的版本、编号、模拟标记及成功条件，不把旧版响应显示为新版操作成功。

新版桥接依赖同目录的 `app_control_guard.py` 和 `motor_register_catalog.py`，对应仓库 `board/` 下三份文件。**本次没有更新开发板上的这些文件。** 后续部署需确认控制空闲、备份原文件并记录哈希、一起安装匹配版本，再核对所有者、权限和文件哈希；不替换已有 GUI、跟随或手动控制程序。

匹配版本部署后的无串口占用检查入口为：

```bash
sudo -n /usr/bin/python3 -B /home/topeet/lianzhan/scripts/app_motor_config_bridge.py --check
```

只有 `ok=true`、`controlAvailable=true`、`serialOpened=false` 才表示该检查通过；这不是实车参数读取或真实写入验证。

## 模拟验证

离线 Python 测试入口：

```text
python -B -m unittest discover -s board -p test_app_motor_config_bridge.py -v
python -B -m unittest discover -s board -p test_app_control_guard.py -v
```

桥接 `--simulate` 每次创建独立内存寄存器，不加载真实控制锁、不打开串口。模拟结果能验证 JSON、编解码、写入模式、回执、限时动作和失败处理流程，不能证明实车参数已变化、实际断电保持或电机动作完成。POSIX 专用检查在 Windows 的跳过项不能记成实机通过。

新版 Android 验证包含模型和严格协议解析、Fake callbacks 界面测试，以及模拟桥接 JSON 的端到端测试。`MotorConfigurationPageTest` 的 15 项已通过，覆盖分类和寄存器搜索、枚举草稿、临时模式预览、动作单独确认、锁定/忙碌/断连撤销、停止独立权限、连接设置不触发 I/O、未确认状态仅允许恢复读取，以及限时动作取消按钮。最终共 133 项 JVM、44 项 Linux 桥接、30 项模拟器测试通过，详见 [完整验证记录](motor-full-validation-2026-10-30.md)。本机日志位于 `app/build/reports/motor-protocol-full/`；界面截图使用固定模拟数值，不是实车读数。
