# 自动跟随误退出的有界恢复（2026-11-09）

本轮只调整已审查、不会重新发送未知运动指令的路径：

- 电机状态读取若完整请求后收到**纯空回执**，滑动 2 秒内允许两次只读恢复；每次额外读取预算仍为 80 ms，第三次失败继续报错退出。部分帧、CRC/协议错误、驱动器故障码和电机写入结果不明的处理不变。
- 板端状态管道瞬时满（`EAGAIN`、未写入任何字节）时丢弃这一帧状态，100 ms 后再发布。部分写入、管道断开，以及持续超过 2 秒未更新状态仍按故障处理。
- 可选录像器初始化、提交帧或叠加层失败时记录一次 `video_recording_unavailable`，停用录像并继续跟随。主摄像头、视觉/深度计算和电机异常仍走原故障路径。
- App 切离“跟随”页时保留跟随和心跳，返回页面仍可主动停止；手动驾驶切页仍请求停车。后台保持跟随的既有行为不变。

这些改动降低短时空回执、管道拥塞和录像故障导致的退出概率。历史两次 `motor_write: no response from driver` 的原始 RS485 事务已经轮转，无法确认它们是 STOP 还是速度写、纯空还是部分回执，因此本轮没有放宽电机写入。2 秒本地租约/状态看门狗、相机与主视觉故障、驱动器故障码仍保留。没有改动电机配置参数。
