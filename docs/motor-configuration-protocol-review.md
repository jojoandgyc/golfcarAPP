## 最重要的协议结论

- 参数配置用 **`0x10` 写入才可断电保存**；`0x06` 写单寄存器是临时设置，断电重启恢复到此前保存值。即使参数只占一个寄存器，也要用 `0x10`、数量 1 来保存。依据为 PDF 第 18／印刷 16 页 §4.4；GUI 的配置按钮也使用 `persist=True` 或 `write_field`。
- 文档没有单独的“保存全部参数”寄存器，没有说明存储介质类型、写入寿命、保存完成延迟，也没有列出每个参数是否需要重新上电才应用。不能擅自增加 EEPROM 保存指令，或把写回读回成功解释为已经完成断电保持测试。
- 一台双路控制器使用 **同一个 Modbus 从站地址**，左右电机由不同寄存器区分，不是默认左地址 1、右地址 2。PDF 默认地址为 1；板端启动脚本默认 `/dev/ttyS0`、115200、从站 1、8N1、RS485 auto。PDF 出厂波特率为 9600，与板端运行默认不同，App 应使用已确认的板端配置。
- 地址是帧内的零基寄存器地址，不是需要再加减 `40001` 的 PLC 展示编号。本文同时列出十六进制和十进制。
- 每个寄存器 16 位，寄存器内高字节在前；32 位参数由高半字、低半字顺序组成。多字参数作为一个逻辑参数用 `0x10` 连续写入，不分成两次 `0x06`。CRC16 在线路上低字节在前。转速有符号值用二进制补码；例如 -500 编码为 `FFFF FE0C`。

建议把以上参数分为“电流与电子驻车”“正反转速度限制”“加减速”三组，读取结果与尚未保存的输入分开；一个字段或一个有明确边界的组单独提交。最大输出电流降低后不得低于任何一侧现有驻车电流，板端同锁读取两侧值作为校验上下文。这由上述明确范围推导，用于防止最终配置组合越界；文档没有说明固件会拒绝、夹紧还是允许暂时不一致，不应把推导写成已验证的固件行为。设备描述 `0x0002` 还提供设备最大电流，实际许可上限应结合有效的设备能力读值及车辆规格，不能把协议 60 A 当作硬件推荐值。

## 零速、控制占用和回执的含义

可读实时转速是右 `0x0009–0x000A`（9–10）、左 `0x0013–0x0014`（19–20），均为有符号 32 位 RPM。参考库 `read_motor_speeds()` 从 `0x0009` 连读 12 字取得左右值；这是读取，并不写目标速度。

**全文没有“禁能完成”“驱动断电”或“停车确认”可读状态位。** 两侧速度为 0 只证明采样时观测零速。实时系统模式 `0x001D`、控制模式 `0x001E`、错误码为 0、PWM 为 0、持有软件锁都不能单独冒充禁能确认；机械抱闸动作也没有本文明确的到位反馈。

建议写入前由板端持有现有两把控制锁，排除 GUI／手动／跟随进程和串口其他使用者，重新检查两侧零速，并保持锁覆盖读取旧值、校验、写入、回执、读回整个过程。读到速度非零、异常／占用或状态未知就拒绝写入；不要为了满足前置条件自动发停车、自由停止、解抱闸或学习指令。对于可能改变当前静止力矩的驻车配置，应明确其动作后果，不能以“当前零速”作为绝对安全保证。

## 通信校验、写入结果与 schema

协议支持 `0x03` 读、`0x06` 单写、`0x10` 多写。有效响应必须核对 CRC、从站地址、功能码和长度；读取还要核对字节数；`0x06` 核对原地址和值；`0x10` 核对起址和数量。参考 `protocol.py` 已实现这些基础检查。

异常功能码分别为 `0x83`、`0x86`、`0x90`。异常码：01 非法功能、02 非法地址、03 非法值、04 设备故障、05 已接收但处理较久、06 忙、08 存储奇偶错误、0A 网关不可用、0B 网关目标无响应。`0x05` 不能当作写完成；没有协议级安全重试／状态查询约定时，不盲目重发保存请求。

`0x10` 的 ACK **不回显写入数据**，只确认起址／数量，因此保存后要用 `0x03` 读取原始字并逐字比较。结果至少区分“未发送”“写入已发送，结果未知”“收到 ACK，读回失败／不匹配”“ACK 和读回均通过”。超时、断线或 CRC 错误不代表未写入；不能自动回滚、重试整个批次或声称仍保持旧值。多个独立字段不是原子事务，部分成功必须逐项报告。

建议每个允许的字段 schema 固定 `key`、分组、地址、字数、signed、rawMin/rawMax、精确倍率、单位、可写功能码、枚举、相关字段约束、PDF 页和歧义提示。普通请求只接受白名单 key、原始整数与预期旧值，不接受任意地址或任意功能码。当前值与用户草稿分开，刷新失败不能把旧缓存当成本次读值。

参考库的 `value_range` 主要是描述字符串，`write_register()` 只检编码后位宽，`encode_scaled()` 会舍入，不能直接当作完整的输入约束。上层应拒绝 NaN／Infinity、布尔冒充整数、小数 RPM、超过两位小数的电流及越界值；金额式十进制转换成精确厘安原值后再写入，避免隐式 round。读取到超出已知 schema 的值，应显示原始值并提示差异，不能为适配 UI 而改写控制器。

## 已确认的文档歧义与实现检查项

除上文的驻车 0、范围、PID 与版本差异外，还存在这些原文问题：

- 从站地址正文写 1–255，帧说明写 1–254，通信寄存器写 0–255，而 0 是广播。当前固定已知从站 1，不提供广播写或广域自动扫描，也不自行决定 255 可用。
- PWM 写 0–10000、倍率 0.1%，会得到 1000% 上限。参考库按 0.1% 实现；不据此构造百分比安全判断。
- 相电流表写无符号 0–65535，参考 `read_motor_status()` 却对 16 位有符号数取绝对值。常见小值相同，但极值解释不一致；配置审核不依赖此转换判断停机。
- 电源电压 `0x001C` 文档直接写 V，未给倍率，不按其他型号经验除以 10。
- 测试控制 `0x0049` 的范围列写 0/1，备注却列 2；停止／学习属于动作区，本版配置页排除。
- 保留范围末端的十六进制与括号十进制多处不匹配；按已明确的有效地址白名单，不按整段范围盲目写入。

后续测试应覆盖：25 A 的保存帧与 PDF 示例一致；u32 大端组合和 signed32 零速；范围边界、驻车与最大电流交叉约束；忙／未知／非零速拒写；保存 ACK 后读回相同及不匹配；写已发送后断线不误报失败回滚；第二字段失败保留第一字段结果；禁止操作区、保留区、通信参数与广播；并确认读取、切页、导出和清理路径没有额外速度、停止、抱闸或驻车写入。

本次已离线调用参考库的纯协议函数核对：25 A 的 `0x10` 保存帧与 `0x06` 临时帧均逐字节等于 PDF 示例；-500 的 signed32 编解码、110000 的双字大端拆分均通过。该验证没有创建串口对象或发送数据，不代替板端安全门控、实际读回与断电保持测试。
