# 普通 STOP 轮速 200 RPM 与跟随退出路径审查（2026-11-09）

## 本次改动

普通 STOP 后的异常轮速阈值由 100 RPM 调为 **200 RPM**：停车宽限结束后，需要连续两次新鲜反馈的任一车轮绝对轮速 **大于 200 RPM** 才触发 `motor_motion_while_stopped`。恰好 200 RPM 不触发。Open_Palm 手势暂停期间原有推车豁免不变，即该状态下 800 RPM 以上的被推动轮速仍只记录、不因这项判定退出。

跟随控制器的最大目标轮速是 200 RPM；因此本项单独的停车后轮速判定不再识别 200 RPM 以内的异常转动。驱动器故障码、串口读写错误和其他运行异常仍由各自路径处理。本轮没有更改电机参数、配置寄存器或 App。

## 验证与部署

- 开发板隔离目录内 105 项模拟测试通过；更新后板端 120 项模拟测试通过。覆盖 200 RPM 边界、连续采样、手势暂停推车及手势恢复。没有驱动实车电机。
- 自动跟随与手动控制均空闲时取得双重控制锁，备份原文件、安装并核对 SHA-256；控制锁正常释放。完整记录见[板端部署记录](follow-stop-200-board-deployment-2026-11-09.json)。
- 可重现补丁：[follow-stop-200-2026-11-09.patch](../board/patches/follow-stop-200-2026-11-09.patch)。实车效果仍需用户手动验证。

## 其他退出路径

以下按当前板端和 App 源码区分“真正退出”与“只停车等待”。并已只读汇总板端诊断目录中最近 15 个会话（2026-11-06 至 11-09）：11 个未记录首次故障且首先由 App 请求停止；1 个旧版普通 STOP 轮速故障（`7a94302ca9a73a93b10f3acfeac033c6`）；2 个 `motor_write: no response from driver`（`9f384c3bb582213c1851bf30d9a0c0b3`、`498403b153cde743865d244d03e3e72b`）；另 1 个先收到 App 停止请求，随后记录 `motor_write: stop_requested`，不能据此认定是独立的写入故障。最近一轮会话 `d8043a0c91c0b881a8af6a164fda5bc4` 是正常 App 停止。

| 入口 | 当前行为 | 抖动误触发可能性与处理意见 |
| --- | --- | --- |
| `continuous_follow/hardware.py` 的电机状态读取 | RS485 默认 150 ms 超时；只有完整请求、空回执才尝试一次 80 ms 的只读恢复。2 秒内再次失败、部分异常帧或协议错误会抛出，导致 worker 退出。 | 较值得优先查看原始 RTU 事务与故障阶段；若证实是短时空回执，再设计有界恢复。 |
| `continuous_follow/hardware.py` 的手势暂停 STOP 刷新 | 暂停期间约每 200 ms 刷新 STOP；当前 `gesture_paused` 不使用周期性 STOP 空回执恢复，一次回执异常就可能退出。 | 与“推车期间退出”相似，但属于停车指令回执问题；先用伪串口复现，再考虑有界重试，不能将发送失败视为停车成功。 |
| `car_control_modular/mssd_motor.py` 的目标轮速写入 | 仅符合完整双寄存器写入、空 ACK 等严格条件时可在约 600 ms 内先 STOP 并验证恢复；部分写入或结果不明会锁存异常退出。 | 曾有 `motor_write: no response from driver` 的现场记录。需核对原始通信事务，不能直接忽略左右轮命令不确定性。 |
| `continuous_follow/hardware.py` 的驱动器故障码 | 任一轮读到非零 `error_code` 即退出；RTU 帧已校验 CRC。 | 保留此判定，出现时应按具体故障码、电源与接线调查。 |
| `board/app_follow_worker.py`、桥接层的内部状态/租约 | worker 状态超过约 2 秒未更新或板端本地租约过期会请求停止；协议错误、状态管道故障也会结束会话。 | 即使手机网络正常，板端卡顿仍可能触发；需用同一 `runId` 对照进程、状态更新和首次错误。 |
| `continuous_follow/runtime.py` 的相机与后台 worker 异常 | 摄像头读取异常、RGB 分辨率不符，或 capture／vision／depth worker 未处理异常可结束跟随；录制器调用异常也可能进入此路径。 | 若故障显示 `worker_failure`，优先查看相机/录制器栈与内核 USB 日志；不属于轮速阈值问题。 |
| App 切离“自动跟随”页 | `MainActivity.kt` 调用 `onControlSurfaceHidden(PAGE_CHANGED)`，`BoardViewModel.kt` 会发送停止请求。 | 这是当前明确的界面规则，不是板端故障；切到后台 `APP_PAUSED` 则不会因页面失焦请求停止。 |
| App 网络中断 | 启用手势的可重连跟随会话只与 SSH 附件分离，车端继续运行并可重新接回；未启用手势时仍按原规则请求停车。 | 该差别是当前配置规则。协议校验异常和后台服务失败仍可能形成显式停止意图。 |

目标丢失、视觉数据暂时停滞、障碍和手势 `PAUSED` 在控制器中一般产生 STOP 或 SEARCH，**自身不会退出 worker**；这些状态同时若发生上述硬件或 worker 异常，仍可能退出。启动阶段还有相机/模型初始化失败及 30 秒总启动期限，属于“无法启动”，不等同于运行中退出。

本轮仅调整普通 STOP 的 200 RPM 阈值。其余入口保留现行处理。**下一项优先调查**是上述两次 `motor_write: no response from driver` 对应的原始 RS485 事务和电源/接线状态，再判断是纯空回执、部分写入还是驱动器未响应；只有确认具体阶段后，才能设计可验证的有界恢复。
